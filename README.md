# Java Data Structures — короткий огляд та приклади

Цей проект містить прості демонстрації базових структур даних у Java. Кожна структура має свій файл-демо у папці `src/` (наприклад, `ArrayListExample.java`, `LinkedListExample.java`, `QueueExamples.java`, тощо). Головний раннер — `Main.java`.

Нижче — короткий опис кожної структури: коли використовувати, як працює, складність операцій, та посилання на файл з прикладом.

- ArrayList (`java.util.ArrayList`) — файл: `ArrayListExample.java`
  - Як працює: динамічний масив; під капотом — звичайний масив, який при переповненні розширюється (копіюванням).
  - Коли використовувати: коли потрібен швидкий довільний доступ (get by index) і часті операції читання.
  - Основні складності: get O(1), add (в кінець) амортизовано O(1), add at index O(n) (через зсув), remove O(n).

- LinkedList (`java.util.LinkedList`) — файл: `LinkedListExample.java`
  - Як працює: двозв'язний список (елементи зберігають посилання на попередній і наступний).
  - Коли використовувати: коли багато вставок/видалень на початку/в кінці або при роботі як deque/queue; не підходить для випадкового доступу за індексом.
  - Основні складності: addFirst/addLast O(1), remove/add в середині за посиланням O(1), доступ за індексом O(n).

- Queue (`java.util.Queue`, `LinkedList`) — файл: `QueueExamples.java`
  - Як працює: інтерфейс FIFO; `LinkedList` може бути реалізацією черги.
  - Коли використовувати: коли потрібно обробляти елементи в порядку надходження (черги задач, BFS тощо).
  - Основні операції: offer/add O(1), poll/remove O(1), peek O(1).

- PriorityQueue (`java.util.PriorityQueue`) — файл: `QueueExamples.java`
  - Як працює: бінарна купа; елемент з найвищим пріоритетом (за Comparator або Comparable) повертається першим.
  - Коли використовувати: планування задач, алгоритми з вибором мін/максу, Dijkstra, A*.
  - Основні складності: add O(log n), poll O(log n), peek O(1).

- Stack (через `ArrayDeque`, також `java.util.Stack`) — файл: `StackExample.java`
  - Як працює: LIFO. Рекомендовано використовувати `Deque` (`ArrayDeque`) замість застарілого `Stack`.
  - Коли використовувати: рекурсивні алгоритми, обходи в глибину без рекурсії, відкат операцій (undo).
  - Основні складності: push/pop/peek O(1).

- Set (`HashSet`, `TreeSet`) — файл: `SetExample.java`
  - HashSet:
    - Як працює: хеш-таблиця; елементи унікальні, порядок невизначений.
    - Коли використовувати: швидка перевірка наявності, унікальні колекції.
    - Основні складності: add/contains/remove O(1) в амортизованому випадку.
  - TreeSet:
    - Як працює: чергове балансоване дерево (через `TreeMap`), зберігає порядок.
    - Коли використовувати: потрібно відсортоване представлення множини або операції типу `headSet`, `tailSet`.
    - Основні складності: O(log n) для основних операцій.

- Map (`HashMap`, `TreeMap`) — файл: `MapExample.java`
  - HashMap:
    - Як працює: хеш-таблиця для ключів -> значень.
    - Коли використовувати: асоціативний масив, коли не потрібен відсортований порядок ключів.
    - Основні складності: put/get/remove O(1) амортизовано.
  - TreeMap:
    - Як працює: балансоване бінарне дерево, зберігає ключі в порядку.
    - Коли використовувати: коли потрібна сортування ключів або навігаційні методи (`firstKey`, `subMap`).
    - Основні складності: O(log n).

- Hash (custom `hashCode` / `equals`) — файл: `HashExample.java`
  - Як працює: об'єкти, які використовуються в `HashSet`/`HashMap` повинні коректно реалізовувати `equals` та `hashCode`.
  - Коли використовувати: якщо ви створюєте власні ключі для мап/сетів — обов'язково перевіряти семантику `equals` та стабільність `hashCode`.
  - Порада: `hashCode` повинен повертати однакове значення для об'єктів, що `equals` повертає true; використовуйте `Objects.hash(...)` або IDE-генерацію.

- Tree (Binary Search Tree) — файл: `BinarySearchTree.java`, `TreeExample.java`
  - Як працює: бінарне дерево, лівий піддерево менше вузла, праве — більше; на демонстрації — проста небалансована реалізація.
  - Коли використовувати: якщо важлива логічна ієрархія або шукаєте навчальний приклад; для продуктивних задач краще використовувати збалансовані структури (`TreeMap`, `TreeSet`, AVL/Red-Black).
  - Основні складності (небалансоване BST): insert/search O(h), де h — висота дерева (в найгіршому випадку O(n), в середньому O(log n) для випадкових вставок).

- Bandit / Judge task — файли: `Bandit.java`, `Judge.java`, `BanditListExample.java`, `BanditJudgesSolution.java`
  - `Bandit` — модель бандита з `id`, ім'ям і назвою групи.
  - `Judge` — модель судді.
  - `BanditListExample` — демонструє список бандитів і глибоке копіювання.
  - `BanditJudgesSolution` — показує, як знайти суддів, які судили всю групу.
  - Ідея розв'язання: для кожного бандита є `Set<Judge>` з тими, хто його судив. Щоб знайти суддів, які судили всю групу, беремо перетин множин усіх бандитів у цій групі.
  - Чому `Set`: він прибирає дублікати та дозволяє швидко робити `retainAll(...)`.
  - Чому `Map<Bandit, Set<Judge>>`: дозволяє напряму зберігати відношення "бандит -> судді".

- Train / Passenger task — файли: `Passenger.java`, `Train.java`, `TrainTaskExample.java`
  - `Train` містить назву, час початку/кінця руху та колекцію `Passenger`.
  - `Passenger` містить прізвище пасажира (`name`) та його місце (`place`).
  - `Train.add(String s, int p)` садить пасажира на потяг або оновлює його місце, якщо прізвище вже є.
  - `Train.remove(String s)` висаджує пасажира з потяга.
  - Глибоке копіювання: `Train(Train other)` створює новий потяг і новий список пасажирів, тому зміни копії не впливають на оригінал.
  - Запит A: знайти пасажирів, які їдуть більш ніж на одному потязі. Для цього будуємо `Map<String, Set<String>>`, де ключ — прізвище, а значення — множина назв потягів.
  - Запит B: за прізвищем знайти, чи їде пасажир, і якщо так — на якому потязі та на якому місці.


Запуск демо

1. Скомпілюйте всі файли у директорію `out`:

```powershell
cd D:\files\JavaProjects\basic_structures\basic_struct
javac -d out src\*.java
```

2. Запустіть головний раннер:

```powershell
java -cp out Main
```

Що побачите у виводі:
- приклад із deep copy для списку бандитів;
- пошук суддів, які судили кожне угрупування повністю.
- приклад із потягами та пасажирами, deep copy потягів, а також запити A і B.
